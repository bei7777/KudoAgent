# Web 工作台

## 启动与资料位置

在项目目录执行 `uv run kudo --env-file .env web`，浏览器访问 `http://127.0.0.1:8765`。服务只监听本机。`--port` 选择端口；顶层参数 `--data-dir` 选择研究目录，例如：

```bash
uv run kudo --env-file .env --data-dir .runtime/data web --port 8765
```

安装后的命令与源码环境一致，页面和样式包含在 wheel 中。运行页面不需要 Node.js；浏览器直接从本机 Python 服务读取资源。

运行设置页面显示模型名称、服务地址、凭据环境变量名称和资料目录，可以执行真实的模型连接检查。密钥从本机环境变量或指定的 dotenv 文件读取，API 不返回密钥值。

## 输入线索

首页的“已知线索”可以直接粘贴多行内容，每行一条，最多 20 条。支持用户名、完整公开主页链接、邮箱、带 `+` 和国家代码的电话号码，以及公共 IP。输入后显示识别类型和规范化后的内容，重复线索合并；无效内容在表单中显示具体错误。识别与校验在本机完成，不调用模型或查询外部站点。

“研究问题与运行选项”可以展开填写。研究问题选填，留空时按照输入的线索类型整理公开资料。请求数量、期限、并发和关联扩展预算可以调整，取值沿用 `ResearchRequest` 和 `Budget` 的验证约束。“填写公开项目示例”会填入 Sherlock 项目的公开 GitHub 主页。

查询范围按输入类型自动采用全部已适配站点。用户名默认使用 8,303 个适配条目，邮箱默认使用 13 个查询站点；主页链接用于提取页面内容和外链，电话号码与 IP 分别查询号码和网络资料。首页显示当前目录数量，研究无需选择站点。

点击“开始研究”后进入“发现资料”。首页下方保留研究记录，可按研究目标搜索并打开已有任务。

## 资料与来源

“发现资料”按照输入类型打开相应分类，并提供以下筛选：

| 分类 | 内容与数量含义 |
| --- | --- |
| 候选页面 | 已发现的账户页面和取得的公开主页，按来源 URL 去重计数；同一页面的多条证据分别保留 |
| 邮箱检查 | 各站点返回的检查记录，包括注册状态、公开头像、公开资料及无法判断的结果 |
| 号码与 IP | 电话号码资料、搜索建议，以及 IP 网络与近似地理资料 |
| 待核查 | 无法判断、访问阻断、限流、不支持及检测规则冲突的记录 |
| 全部记录 | 完整采集记录，包含发现、未发现和无法判断的结果 |

分类数量覆盖整个任务，搜索与分页仅改变当前显示的记录。可以按站点、线索、来源地址或摘要搜索。候选页面的计数与证据条数分别保留；检测规则共享一次响应时，仍能逐条查看其判断与冲突。

每条证据标注查询类型、时间、观察状态与来源。展开后可以查看检测规则、提取字段和关系记录。同名、页面外链、标识符提及和用户确认分别显示；同名页面保留为候选线索。邮箱记录保留具体接口的检查含义，公开头像与公开资料检查具有各自的结果说明。

原始资料通过应用的内容校验后返回；页面显示前 100,000 字节文本，完整内容以附件下载。二进制资料提供大小与下载入口。资料保存后即可查看，报告生成期间仍可以检索已有记录。

“研究报告”显示模型保存的结论、支持证据与冲突证据。引用链接直接打开对应证据，并提供返回资料列表的入口。Markdown 和 JSON 下载来自相同的报告接口。

## 执行与任务管理

页面每两秒读取进度；所有数字来自应用状态。“执行记录”保留初始查询范围、已返回结果、连接失败、查询受限和待执行数量，并展示请求预算、研究期限、采集批次、模型查询理由及证据引用。初始范围每批执行 50 项。已返回结果可能包含未发现、未知、限流或阻断状态。

失败与受限列表显示最近 20 项及其原因，完整记录保存在报告中。结束原因和程序错误也可以在执行详情中查看。

取消按钮终止任务。对于已取消、中断或失败的任务，可以点击“恢复研究”。存在未确认完成的账户请求时，页面显示对应数量，重新发送需要明确勾选。服务正常退出时会中断任务并完成现有状态保存；重新启动后从任务列表继续操作。

“重新研究”将现有线索、问题和预算填入首页表单，提交后创建独立记录。结果比较选择两项研究，逐条展示新增、不再发现、内容变化、暂时无法核查、没有再次查询和保持一致的内容。

研究结束后，可以在“确认关系”中选择已经出现在资料中的两个公开地址，并填写确认声明；声明以 `user_confirmed` 单独保存并补充到报告。

## 站点目录与页面设计

站点目录默认展示用户名站点，每页显示 30 项，顶部和底部均提供分页按钮。搜索支持中文名称、英文名称和域名；“国内站点”依据上游规则的 `cn` 标签筛选，当前包含 137 项，其中 131 项规则已适配。目录同时展示受限规则及其具体原因。微博规则需要专门会话，哔哩哔哩规则需要数字 UID，均保留对应限制说明。切换“邮箱查询站点”可以查看各接口的检查含义与已有实测记录。

工作台使用黑白主体、细线分隔与等宽数据文字，主导航提供研究、站点目录、结果比较和运行设置。页面针对窄屏调整布局，输入框与按钮提供键盘焦点提示。字体使用本机字体，页面资源全部由本机服务提供。

视觉方向依据用户提供的黑白界面参考，设计检查使用 Damir Sokolovsky 的 [unslop](https://github.com/heydamir/unslop) skill（CC BY 4.0）。界面代码在本项目中独立实现。

## 代码组织

| 位置 | 职责 |
| --- | --- |
| `application/intake.py` | 多行线索识别、去重、校验与研究请求准备 |
| `application/service.py` | 共用任务操作、历史分页、资料筛选与统计、研究详情与原始资料读取 |
| `integrations/web.py` | Starlette 生命周期、JSON 输入验证、本机访问检查与 HTTP 路由 |
| `integrations/web_static/index.html` | 页面结构与主要导航 |
| `integrations/web_static/app.js` | 首页输入表单、页面路由、真实 API 请求、任务轮询与交互 |
| `integrations/web_static/app.css` | 桌面和窄屏布局、键盘焦点、显示样式 |

Web 服务使用一个 `Application` 实例管理后台任务；CLI 与 MCP 保持原有入口。历史查询直接读取已有 SQLite 数据。页面中的外部内容通过 DOM 文本节点显示，原始响应采用附件下载，页面资源来自本机。

服务验证 Host、Origin 和浏览器来源信息；变更请求同时要求当前进程生成的页面令牌。重启后旧令牌失效，刷新页面即可取得新会话。接口错误返回明确的错误状态，未处理的程序异常由服务日志记录。

## 验证

基础验证使用实际 Starlette 应用、SQLite、规则目录和官方测试客户端：

```bash
uv run pytest tests/test_web.py tests/test_intake.py tests/test_evidence_browser.py
```

启动已配置模型的工作台后，执行真实浏览器验收。macOS 可以使用已安装的 Google Chrome：

```bash
uv run python scripts/verify_web_browser.py --browser-executable "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --output .runtime/web-browser/results.json
```

浏览器验收使用已配置的真实模型服务与 Sherlock 项目的公开 GitHub 主页。检查内容包括多行输入识别、重复线索、错误提示、选填问题、完整查询范围、资料分类与搜索、引用定位、执行进度、原始资料校验、报告下载、取消恢复、比较、站点目录和窄屏布局。结果保存在 `.runtime/`，实际通过情况以验证记录为准。

`tests/test_evidence_browser.py` 的采集记录测试需要 `KUDO_CAPTURED_COLLECTORS` 和 `KUDO_CAPTURED_RESEARCH` 分别指向已有公开资料采集数据库与包含规则冲突、邮箱检查的研究数据库。测试以只读方式复制数据库，再在独立测试目录检查筛选、统计和引用；未配置记录路径时跳过对应测试。
